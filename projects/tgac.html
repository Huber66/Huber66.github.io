把查询结果转换为指纹，与已知错误样本比较，利用限次重试反馈引导修改。最终提交的 SQL 会重新执行并保存实际结果。

RESULT CHECK · RETRY · RE-EXECUTION
02

执行流程

单题运行由上下文构造、Agent 工具调用和提交检查衔接。执行过程中产生的 SQL、查询结果与反馈共同组成可回看的轨迹。

  1. 构造上下文

    读取业务问题、相关表结构和知识资料，组装当前任务的提示词。

  2. 查询与修正

    执行样本探查和完整 SQL，根据数据或报错调整查询与规划。

  3. 检查提交

    将提交结果与错误样本比较，按重试策略返回反馈或结束图流程。

  4. 重执行与保存

    重新执行最终 SQL，将实际返回值写入 JSON，保留逐步运行记录。

运行之间，通过答案管理工具维护正确、错误样本，并从参考 SQL 或待分析任务中提炼 Logic Guide。阅读完整方案与知识维护流程 ↗
